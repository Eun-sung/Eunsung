# RSI 워치 iOS 앱 제작 지시서

이 문서는 현재 운영 중인 웹앱 "RSI 워치"를 **나와 지인만 쓰는 아이폰 앱**으로 만들기 위한 검토 결과, 기획, 작업 지시를 한곳에 모은 것입니다. 작업자(사람 또는 AI 코딩 에이전트)는 이 문서만 읽고 작업을 시작할 수 있어야 합니다.

- 작성 기준일: 2026-11-17
- 저장소: `Eun-sung/Eunsung` (배포 브랜치 `master`)
- 애플 정책·한도·요금은 바뀔 수 있으므로, 각 단계에 들어가기 전에 공식 문서에서 다시 확인합니다.

---

## 1. 결론: 가능한가

**가능합니다.** 앱스토어 검색에 노출하지 않고 나와 지인만 설치하게 하는 공식 방법이 있습니다. 다만 "앱스토어에 공개 출시"가 아니라 아래 두 방식 중 하나를 씁니다.

| 방식 | 누가 설치하나 | 심사 | 유지 부담 | 판단 |
|---|---|---|---|---|
| **TestFlight** | 이메일로 초대한 사람만. 내부 100명, 외부 10,000명까지 | 내부 테스터는 심사 없음. 외부 테스터는 첫 빌드에 베타 심사 | 빌드가 **90일 뒤 만료**되어 주기적으로 새 빌드를 올려야 함 | **1차 권장** |
| **비공개 링크 배포(Unlisted)** | 링크를 아는 사람만. 검색·차트에 안 나옴 | 정식 앱 심사 + 애플에 별도 신청·승인 필요 | 만료 없음 | 2차 선택(안정화 뒤) |
| Ad Hoc | 기기 식별자를 등록한 기기만(연 100대) | 없음 | 지인 기기마다 식별자 수집, 1년마다 재서명 | 비권장 |
| 무료 계정 설치 | 본인 기기만 | 없음 | 7일마다 재설치, 푸시 불가 | 불가 |

**권장 경로**: TestFlight로 시작합니다. 본인은 내부 테스터, 지인은 외부 테스터(이메일 초대)로 둡니다. 몇 달 써 보고 계속 쓸 가치가 확인되면 비공개 링크 배포를 신청합니다.

### 꼭 알고 시작해야 할 조건

1. **애플 개발자 프로그램 가입이 필수입니다.** 연 99달러(한국 결제 기준 약 13만 원)이고, 어느 방식이든 필요합니다.
2. **Mac이 없어도 진행할 수 있게 설계합니다.** 빌드는 GitHub Actions의 macOS 실행기에서 하고 TestFlight로 바로 올립니다. 단, Mac 없이 만들면 화면을 눈으로 확인하는 과정이 "빌드 → TestFlight 설치 → 확인"이라 한 번에 15~30분씩 걸립니다. Mac을 빌릴 수 있으면 훨씬 빠릅니다.
3. **시세 데이터 사용 권리가 가장 큰 위험입니다.** 지금은 Yahoo Finance 비공식 API와 본인 명의 한국투자증권 API 키를 씁니다. 혼자 쓸 때는 문제가 드러나지 않지만, 지인에게 값을 제공하면 한국투자증권 약관의 시세 재배포 제한에 걸릴 수 있고, 애플 심사에서 데이터 사용 권리를 물을 수 있습니다. 5.1절의 결정이 끝나기 전에는 외부 테스터 배포를 하지 않습니다.
4. **위젯은 네이티브 앱이어도 실시간이 아닙니다.** iOS가 갱신 횟수를 제한합니다. 서버 푸시로 위젯을 갱신하는 기능(iOS 26)이 있지만 전달이 보장되지 않습니다. "앱을 열면 실시간, 위젯은 수 분 지연"이 현실적인 목표입니다.
5. **개인 계정으로 배포하면 TestFlight와 앱스토어에 본인 실명이 판매자로 표시됩니다.**

### 앱을 만들지 않는 대안

지인도 지금의 웹앱(PWA)과 Scriptable 위젯을 쓰게 하는 방법이 있습니다. 비용이 없고 심사도 없습니다. 다만 현재 웹앱은 설정이 하나뿐이라 모두가 같은 종목·기준을 보게 되고, 알림은 각자 텔레그램을 연결해야 합니다. 네이티브 앱을 만들 이유는 **사람마다 다른 종목·기준, 텔레그램 없는 푸시 알림, 제대로 된 위젯** 세 가지입니다.

## 2. 현재 시스템 (작업의 출발점)

Cloudflare Worker 하나가 화면(PWA), API, 5분 주기 알림 확인을 모두 처리합니다.

| 파일 | 역할 |
|---|---|
| `src/rsi.js` | 주봉 RSI(14) 계산. Wilder 평활, 현재가에서의 RSI, 목표 RSI가 되는 가격 역산 |
| `src/yahoo.js` | Yahoo Finance 차트 API로 주봉과 5분봉(프리·애프터마켓 포함) 조회 |
| `src/kis.js` | 한국투자증권 Open API로 미국 주간거래(뉴욕 20:00~04:00) 5분봉 조회. 키가 있을 때만 동작 |
| `src/worker.js` | API 라우팅, 종목 분석(`analyze`), 텔레그램 알림(`checkAlerts`), 크론 진입점 |
| `public/` | PWA 화면 (`index.html`, `app.js`, `style.css`) |
| `test/rsi.test.mjs` | RSI 계산 검증 (`npm test`) |
| `scripts/dev.mjs` | 로컬 확인용 서버 (`npm run dev`) |

현재 API:

- `GET /api/data` — 종목별 RSI, 가격, 세션, 차트용 추이(주봉 52개, 5분봉 5일)
- `GET /api/summary` — 위젯용 요약(종목, RSI, 지난주 대비 변화, 기준 이하 여부)
- `POST /api/config`, `POST /api/telegram/connect`, `POST /api/telegram/test` — `x-pin` 헤더 필요

현재 저장소(KV): `config`(종목·기준·텔레그램 대화방), `state`(알림 상태), `kis_token`(한국투자증권 토큰).
현재 시크릿: `TELEGRAM_BOT_TOKEN`, `APP_PIN`, `KIS_APP_KEY`, `KIS_APP_SECRET`.

핵심 계산 규칙(바꾸지 않습니다):

- 이번 주 봉의 종가 자리에 현재가를 넣어 주봉 RSI를 계산합니다.
- 현재가 우선순위: 정규장 가격 → 그보다 새로운 프리·애프터마켓 5분봉 → 그보다 새로운 주간거래 5분봉.
- 뉴욕 일요일 18시 이후의 가격은 새 주의 봉으로 계산합니다.
- 알림은 기준 이하로 내려간 순간 한 번, 기준 +1 위로 회복한 뒤 다시 내려가면 또 보냅니다.

## 3. 제품 기획

### 3.1 대상과 규모

- 사용자: 본인과 지인. 설계 상한 **20명**, 1인당 **종목 10개**.
- 서버가 추적하는 서로 다른 종목은 **최대 15개**로 제한합니다(Cloudflare 무료 플랜의 호출당 외부 요청 50회 제한 때문. 종목당 최대 3회 요청).

### 3.2 1차 범위 (v1)

1. **종목별 주봉 RSI 화면** — 현재 웹앱과 같은 정보: RSI(소수 둘째 자리), 지난주 대비 ▲▼, 기준까지 거리, 기준이 되는 가격, 최근 5일·1년 차트, 세션 표시. 앱이 화면에 있는 동안 15초마다 갱신.
2. **개인별 종목·기준 설정** — 사용자마다 따로 저장.
3. **푸시 알림** — 기준 이하로 내려가면 애플 푸시로 알림. 텔레그램 불필요.
4. **위젯** — 홈 화면(소·중), 잠금 화면(한 줄, 사각형). "몰래 보기" 옵션: 종목 첫 글자만 표시.
5. **초대 코드 가입** — 초대 코드를 아는 사람만 등록 가능. 계정·이메일·비밀번호 없음.

### 3.3 v1에서 하지 않는 것

- 주식 매매, 계좌 연동, 투자 조언 문구
- 주봉 RSI(14) 외의 지표, 다른 봉 주기
- 안드로이드, 아이패드 전용 화면, 애플워치
- 결제, 광고, 분석 도구(사용 기록 수집 없음)
- 기존 웹앱과 텔레그램 알림의 제거(그대로 둡니다. 4.2절 참고)

## 4. 설계

### 4.1 구성

```
iPhone 앱 (SwiftUI)  ──HTTPS──▶  Cloudflare Worker (기존 확장)
위젯 (WidgetKit)     ──HTTPS──▶    ├─ D1: 사용자·기기·관심종목·알림상태
        ▲                          ├─ KV: 시세 토큰 등 기존 값
        └──── APNs 푸시 ◀──────────└─ 크론(5분): RSI 계산 → 푸시 발송
                                        ▲ Yahoo / 한국투자증권 시세
```

- 앱은 RSI를 직접 계산하지 않고 서버 값을 표시합니다. 계산 규칙이 한곳(`src/rsi.js`, `analyze`)에만 있도록 유지합니다.
- 앱과 위젯은 App Group으로 인증 토큰과 설정을 공유합니다.

### 4.2 서버 변경 (기존 Worker 확장)

기존 경로(`/api/data`, `/api/summary`, 텔레그램, PIN)는 **그대로 두고**, 앱용 경로를 `/v1/` 아래에 새로 만듭니다. 기존 웹앱이 깨지면 안 됩니다.

**저장소**: Cloudflare D1을 추가합니다.

| 테이블 | 열 |
|---|---|
| `users` | `id`, `name`, `token_hash`, `created_at`, `last_seen_at` |
| `devices` | `id`, `user_id`, `apns_token`, `widget_push_token`(선택), `environment`(sandbox/production), `updated_at` |
| `watches` | `user_id`, `symbol`, `threshold`, `below`(알림 상태), `changed_at` — 기본키 (`user_id`, `symbol`) |
| `invites` | `code_hash`, `max_uses`, `used`, `expires_at` |

**API** (모두 JSON, `/v1/register` 외에는 `Authorization: Bearer <토큰>` 필요):

| 경로 | 동작 |
|---|---|
| `POST /v1/register` | `{invite, name}` → `{token}`. 초대 코드 확인 후 무작위 32바이트 토큰 발급. 서버에는 해시만 저장. IP당 분당 5회 제한 |
| `GET /v1/watchlist` | 내 종목 목록 |
| `PUT /v1/watchlist` | `{items:[{symbol, threshold}]}` 전체 교체. 종목 코드 형식·기준 범위(0~100)·개수(10)·시세 조회 가능 여부·전체 종목 수(15) 검증. 기준이 바뀐 종목은 알림 상태 초기화 |
| `GET /v1/data` | 내 종목의 상세(현재 `/api/data`의 `symbols`와 같은 모양) |
| `GET /v1/summary` | 내 종목의 요약(현재 `/api/summary`의 `items`와 같은 모양) |
| `PUT /v1/device` | `{apnsToken, widgetPushToken?, environment}` 등록·갱신 |
| `POST /v1/test-push` | 내 기기로 시험 알림 발송. 사용자당 분당 1회 |
| `DELETE /v1/me` | 내 데이터 전체 삭제(심사 요건) |

**관리**: 초대 코드 생성·사용자 삭제는 기존 `APP_PIN`으로 보호되는 `POST /v1/admin/invite`, `DELETE /v1/admin/user/:id`로 처리합니다. 관리 화면은 만들지 않습니다.

**크론**: 5분마다

1. `watches`의 서로 다른 종목을 구해 종목당 한 번만 `analyze`를 실행합니다.
2. 각 관심종목 행에 대해 현재 알림 규칙(기준 이하 진입 시 1회, +1 회복 시 재준비)을 적용합니다.
3. 알림 대상 기기에 APNs로 발송합니다. APNs가 "더 이상 유효하지 않은 토큰"으로 응답하면 그 기기 행을 지웁니다.
4. 기존 `checkAlerts`(텔레그램)는 그대로 함께 실행합니다.

**APNs 발송**: Worker에서 `.p8` 키로 ES256 JWT를 만들어 `api.push.apple.com`(개발 빌드는 `api.sandbox.push.apple.com`)에 보냅니다. JWT는 50분 동안 재사용합니다. 새 시크릿: `APNS_KEY_P8`, `APNS_KEY_ID`, `APNS_TEAM_ID`, `APNS_BUNDLE_ID`.

> **먼저 검증할 것**: Cloudflare Worker의 `fetch`로 APNs(HTTP/2 전용)에 실제로 보낼 수 있는지 M1에서 확인합니다. 안 되면 대안은 (가) 푸시만 중계하는 작은 외부 서비스, (나) v1에서는 텔레그램 알림을 유지하는 것입니다. 이 결과에 따라 3.2절의 3번이 바뀔 수 있으므로 가장 먼저 합니다.

### 4.3 iOS 앱

- **기술**: Swift, SwiftUI, WidgetKit, Swift Charts. 외부 라이브러리 없이 작성합니다.
- **최소 버전**: iOS 17. 위젯 푸시 갱신은 iOS 26 이상에서만 켭니다.
- **프로젝트 생성**: XcodeGen(`project.yml`)으로 만들어, Xcode 프로젝트 파일을 저장소에 넣지 않습니다. Mac 없이도 구성 변경을 검토할 수 있게 하기 위함입니다.
- **타깃**: 앱 `RSIWatch`, 위젯 확장 `RSIWatchWidget`, 공용 코드 `Shared`(API 클라이언트, 모델, 표시 형식).
- **저장**: 인증 토큰은 키체인(App Group 공유), 화면 설정은 App Group `UserDefaults`.

**화면**

1. **시작(등록)** — 초대 코드와 이름 입력 → 등록 → 알림 권한 요청. 권한을 거부해도 앱은 동작합니다.
2. **메인** — 맨 위 한 줄 요약, 종목 카드 목록(웹앱과 같은 구성). 당겨서 새로고침. 앱이 보이는 동안 15초마다 갱신하고, 백그라운드에서는 멈춥니다.
3. **설정** — 종목 추가·삭제·기준 수정, 시험 알림 보내기, "몰래 보기" 토글, 내 데이터 삭제, 면책 문구와 개인정보 처리방침 링크.

**상태 처리**: 불러오는 중, 종목 없음, 네트워크 오류(마지막 값과 그 시각을 계속 표시), 인증 만료(등록 화면으로)를 각각 구현합니다. 숫자는 고정폭 숫자 글꼴을 씁니다. 다크·라이트 모드와 글자 크기 조절을 지원합니다.

**위젯**

| 종류 | 내용 |
|---|---|
| 홈 화면 소 | 종목 최대 4개: 이름, RSI, ▲▼ |
| 홈 화면 중 | 종목 최대 4개: 이름, RSI, ▲▼ 변화 폭, 기준까지 거리 |
| 잠금 화면 한 줄 | `T 39.37 S 37.68` 형태 |
| 잠금 화면 사각형 | 종목 최대 3개 |

- 타임라인은 15분 뒤 갱신을 요청합니다(실제 시점은 iOS가 정합니다).
- 기준 이하인 종목은 홈 화면에서 색으로, 잠금 화면에서 `▼` 기호로 구분합니다.
- 위젯을 누르면 앱이 열립니다.
- iOS 26 이상: 서버가 알림을 보낼 때 위젯 푸시도 함께 보내 위젯을 갱신합니다. 전달이 보장되지 않으므로 보조 수단으로만 씁니다.

### 4.4 빌드와 배포 (Mac 없이)

- GitHub Actions 워크플로 `ios.yml`: macOS 실행기에서 XcodeGen → 단위 테스트 → 보관(archive) → TestFlight 업로드.
- 서명: App Store Connect API 키로 자동 서명합니다. 저장소 시크릿: `ASC_KEY_ID`, `ASC_ISSUER_ID`, `ASC_KEY_P8`.
- 실행 조건: `ios/` 아래 변경이 `master`에 들어갈 때, 그리고 **매월 1일 자동 실행**(TestFlight 90일 만료 방지).
- 빌드 번호는 실행 번호로 자동 증가시킵니다.
- 비용: 저장소가 비공개이면 macOS 실행 시간은 무료 한도에서 10배로 차감됩니다(월 2,000분 한도 기준 약 200분, 빌드 약 15회). 한도를 넘지 않게 불필요한 실행을 막습니다.

## 5. 시작 전에 정해야 할 것

### 5.1 시세 데이터 (외부 배포 전 필수 결정)

| 선택지 | 내용 | 평가 |
|---|---|---|
| A. 현행 유지 | Yahoo 비공식 + 본인 한국투자증권 키 | 본인만 쓰는 내부 테스트 단계에서만 허용 |
| B. 주간거래 제외 | 지인에게는 Yahoo 기반 값만 제공 | 한국투자증권 약관 문제는 피하지만 Yahoo 비공식 문제는 남음 |
| C. 정식 라이선스 시세 | 재배포가 허용된 유료 시세 API로 교체 | 가장 안전. 월 비용 발생. 주간거래 지원 여부는 공급자별 확인 필요 |

**권장**: 내부 테스트(M1~M4)는 A로 진행하고, 지인 초대(M5) 전에 한국투자증권 Open API 약관의 시세 제3자 제공 조항을 확인한 뒤 B 또는 C를 고릅니다. 약관 확인은 이 문서 작성 시점에 하지 못했습니다.

### 5.2 그 밖의 결정

| 항목 | 권장 기본값 |
|---|---|
| 앱 이름 | `RSI 워치` |
| 번들 ID | `com.<본인이 정하는 이름>.rsiwatch` |
| 지인 수 | 20명 이내 |
| 알림 채널 | 애플 푸시(검증 실패 시 텔레그램 유지) |
| 장기 배포 | TestFlight 유지, 3개월 뒤 비공개 링크 배포 검토 |

## 6. 본인이 직접 해야 하는 일

작업자가 대신할 수 없는 일입니다. 발급받은 키는 채팅이나 저장소에 붙여넣지 말고, 지정된 시크릿 저장 위치에만 넣습니다.

1. **애플 개발자 프로그램 가입** — 아이폰의 Apple Developer 앱에서 개인으로 가입하고 결제합니다. 승인에 하루 이상 걸릴 수 있습니다.
2. **App Store Connect API 키 발급** — 사용자 및 액세스 → 통합 → 키 생성(앱 관리 권한). `.p8` 파일은 한 번만 내려받을 수 있습니다. → GitHub 저장소 시크릿에 등록.
3. **푸시 알림 키 발급** — 개발자 계정의 인증서·식별자·프로파일 → 키 → Apple Push Notifications service 선택. → Cloudflare 시크릿에 등록.
4. **App Store Connect에서 앱 항목 생성** — 이름, 번들 ID.
5. **TestFlight 테스터 초대** — 본인을 내부 테스터로, 지인을 외부 테스터로(이메일).
6. **지인에게 초대 코드 전달** — 메신저로 따로 전달합니다.
7. **개인정보 처리방침 확인** — 작업자가 초안을 만들면 내용을 확인합니다(외부 테스터 배포에 URL이 필요합니다).

## 7. 작업 순서와 완료 기준

각 단계는 완료 기준을 **실제로 실행해서** 확인한 뒤 다음으로 넘어갑니다. 확인하지 못한 항목은 "미확인"이라고 보고합니다.

### M0. 준비
- 6절의 1~4번 완료 여부를 확인하고, 안 된 것이 있으면 그 목록만 보고하고 서버 작업(M1)부터 진행합니다.

### M1. 푸시 발송 검증 (가장 먼저)
- Worker에서 APNs로 시험 푸시를 보내는 최소 코드를 작성합니다.
- 완료 기준: APNs가 정상 응답(HTTP 200)을 돌려준다. 실제 기기 수신 확인은 M3 뒤로 미룹니다.
- 실패 시: 4.2절의 대안을 정리해 보고하고 결정을 받습니다.

### M2. 서버 다중 사용자화
- D1 스키마, `/v1/*` API, 크론의 사용자별 알림 평가를 구현합니다.
- 완료 기준:
  - 초대 코드가 틀리면 등록이 거부되고, 맞으면 토큰이 발급된다.
  - 토큰 없이 `/v1/*`를 부르면 401이 온다. 다른 사용자의 데이터는 읽거나 바꿀 수 없다.
  - 두 사용자가 같은 종목에 다른 기준을 두면 알림이 각자 기준에 따라 따로 판정된다(가짜 시세로 시험).
  - 기존 `/api/data`, `/api/summary`, 텔레그램 알림, 웹앱 화면이 이전과 똑같이 동작한다.
  - `npm test`가 통과하고, 알림 판정과 인증에 대한 테스트가 추가되어 있다.

### M3. 앱 뼈대와 배포 파이프라인
- XcodeGen 프로젝트, 등록 화면, 요약만 보여주는 메인 화면, `ios.yml`.
- 완료 기준: GitHub Actions 빌드가 성공하고, 본인 아이폰의 TestFlight에서 설치해 등록 후 실제 RSI 값이 보인다.

### M4. 앱 기능 완성
- 종목 카드와 차트, 설정, 푸시 알림, 위젯 4종, "몰래 보기".
- 완료 기준:
  - 웹앱과 앱의 RSI 값이 같은 시각에 소수 둘째 자리까지 일치한다.
  - 시험 알림이 잠금 화면에 도착한다.
  - 기준을 현재 RSI보다 높게 바꾸면 5분 안에 실제 알림이 온다.
  - 위젯 4종이 홈·잠금 화면에 추가되고 값이 표시된다.
  - 비행기 모드에서 앱을 열면 마지막 값과 오류 안내가 보이고 멈추지 않는다.

### M5. 지인 배포
- 5.1절 결정 반영, 개인정보 처리방침 게시, 면책 문구("투자 조언이 아니며 시세는 지연되거나 틀릴 수 있음"), 베타 심사 제출 정보 작성.
- 완료 기준: 외부 테스터 한 명이 초대 메일로 설치해 등록·알림 수신까지 마친다.

### M6. (선택) 비공개 링크 배포
- 정식 심사 제출 후 애플의 비공개 배포 신청 양식을 계정 소유자가 제출합니다.
- 심사 대비: 심사자가 쓸 초대 코드를 심사 메모에 적고, 데이터 삭제 기능과 개인정보 처리방침을 갖춥니다.

## 8. 작업 원칙

- **기존 서비스를 깨지 않습니다.** `master`에 올리면 곧바로 운영에 반영되므로, 서버 변경은 로컬(`npm run dev`)과 테스트로 확인한 뒤 올리고, 올린 뒤 실제 주소에서 `/api/summary`를 조회해 확인합니다.
- **비밀값을 코드·문서·로그에 남기지 않습니다.** 토큰과 키는 시크릿 저장소에만 둡니다. 서버에는 사용자 토큰과 초대 코드의 해시만 저장합니다.
- **수집하는 개인정보는 이름(별명), 푸시 토큰, 관심종목뿐입니다.** 그 밖의 것은 추가하지 않습니다.
- **RSI 계산 규칙은 `src/rsi.js`와 `analyze`에만 둡니다.** 앱에 계산을 복제하지 않습니다.
- **요청하지 않은 기능을 넣지 않습니다.** 3.3절의 항목이 필요해 보이면 구현하지 말고 제안으로 보고합니다.
- **보고는 사실대로 합니다.** 실행해 확인한 것, 확인하지 못한 것, 실패한 것을 구분해 적습니다.

## 9. 알려진 위험과 미해결 항목

| 항목 | 내용 | 대응 |
|---|---|---|
| 시세 사용 권리 | 5.1절 | M5 전에 결정 |
| Worker → APNs 가능 여부 | HTTP/2 전용 서버로의 발송이 되는지 미확인 | M1에서 검증 |
| 위젯 푸시 신뢰도 | iOS 26 위젯 푸시가 전달되지 않는 사례 보고가 있음 | 보조 수단으로만 사용 |
| 심사 거절 | 기능이 단순하다는 이유, 금융 정보 앱이라는 이유로 질문받을 수 있음 | 면책 문구, 매매 기능 없음 명시, 초대 코드 제공 |
| Yahoo 비공식 API | 예고 없이 막힐 수 있음 | 시세 조회부를 교체 가능한 구조로 유지 |
| 한국투자증권 키 만료 | 1년마다 갱신, 갱신 시 키 변경 | 만료 한 달 전 Cloudflare 시크릿 교체 |
| TestFlight 90일 만료 | 새 빌드가 없으면 앱이 열리지 않음 | 매월 자동 빌드 |
| Mac 없는 개발 | 화면 확인 주기가 길고 디버깅이 어려움 | 화면 로직을 단위 테스트로 최대한 확인, 가능하면 Mac 대여 |
